# Enzyme Constraints with GECKO 3.0 Protocol

The three tripartite cell models (iMMU1868a-pap, iMMU1868n-pre, and iMMU1868n-post) were converted into enzyme-constrained models using the GECKO 3.0 protocol. The reconstruction followed the GECKO full ecModel protocol:
https://github.com/SysBioChalmers/GECKO/blob/main/tutorials/full_ecModel/protocol.m

A protein-pool constraint was applied to each model using Sharma et al. proteomics of the form sum(v_i / kcat_i) <= Ptot * sigma * f

Final enzyme-constrained models generated by the protocol are stored as: ecMMU1868a-pap.yml, ecMMU1868n-pre.yml, and ecMMU1868n-post.yml in results/06_enzyme_constraints_GECKO folder.

Each cell folder contains the adapter file (.m), protocol script (.m), data/ (cached protocol inputs), models/ (input GEM plus all stage and final .yml model states), and output/ (tunedKcats.tsv and run_log.txt from the original build).

Data files:
The data/ folder holds all inputs required for the build, including DLKcat.tsv (the cached DLKcat kcat predictions, which the protocol reads instead of re-running DLKcat through Docker), ComplexPortal.json, smilesDB.tsv, proteomics.tsv, uniprotConversion.tsv, and the cell-type LFQ proteomics.

Two large database files are not included because they exceed the GitHub file-size limit: kegg.tsv (120 MB) and uniprot.tsv (37 MB). GECKO regenerates them on first run using the organism keys set in the adapter file (kegg.ID = mmu and uniprot taxonomy ID = 10090), writing fresh copies into each cell's data/ folder. Note that because these are downloaded fresh, they reflect the current state of the KEGG and UniProt databases; if those have been updated since the original build, kcat matching may differ slightly. Exact reproduction of the published models can be obtained using the cached DLKcat.tsv file included in the repository.

Outputs:
Model output from each stage is saved as .yml (keeps the enzyme constrained structure) in each cell's models/ folder, and the final models are also copied to results/06_enzyme_constraints_GECKO together with the tuned kcat tables. The .mat version of each final ecModel (about 320 MB each, used by the downstream SteadyCom step) are not stored in the repository because it exceeds the GitHub file-size limit. It is regenerated from the final .yml (load with loadEcModel, then save as .mat), and archived on Zenodo at https://doi.org/10.5281/zenodo.20606464.
